# 사용자 시나리오 기반 흐름 문서 (커밋 금지)

이 문서는 **내부용**입니다. “회원가입 → 비밀번호 찾기 → 로그인 → 게시물 작성/수정/삭제” 시나리오에서 **클라이언트(브라우저)와 서버(Express) 사이**에 어떤 요청/응답이 오가고, 어떤 라이브러리/코드가 관여하는지 단계별로 정리합니다.

> 전제: 이 프로젝트는 EJS SSR 페이지 + 일부 fetch/AJAX(JSON) 요청을 혼합합니다. 또한 세션 기반 인증(Passport + express-session), CSRF 토큰 검증, 레이트 리밋을 적용합니다.

---

## 0) 공통 전제: 세션/CSRF 토큰 준비

### 0-1. 사용자가 로그인/회원가입/비밀번호 찾기 페이지에 진입

- **클라이언트**: 브라우저가 `GET /login` 또는 `GET /signup` 또는 `GET /reset-password` 요청
- **서버**:
  - `ensureCsrfToken`이 세션에 CSRF 토큰을 만들고(`req.session.csrfToken`)
  - EJS 렌더링 시 `csrfToken`을 템플릿 변수로 내려줌

### 0-2. CSRF 토큰이 포함되는 방식

- **HTML Form**: `<input type="hidden" name="_csrf" value="<%= csrfToken %>">`
- **fetch/AJAX**: `X-CSRF-Token: <meta name="csrf-token" ...>` 헤더로 전송

### 0-3. 관련 코드/라이브러리

- **서버 코드 위치**: `index.js`의 `ensureCsrfToken`, `requireCsrf`, `renderWithCsrf`
- **라이브러리**
  - `express-session`: 세션 저장소(기본 메모리 스토어)
  - `cookie-parser`: 쿠키 파싱(세션 쿠키/헤더 처리)
  - `crypto`: CSRF 토큰 생성, 업로드 파일명 랜덤화

## 1) 시나리오 1: 회원가입(Sign up)

### 1-1. 회원가입 페이지 접속

- **클라이언트**: `GET /signup`
- **서버**: EJS `views/signup.ejs` 렌더링 + `csrfToken` 주입

### 1-2. 폼 제출

- **클라이언트**: `POST /signup` (form-urlencoded)
  - body: `id`, `pw`, `em`, `nm`, `_csrf`
- **서버**: 라우트 핸들러
  - `requireCsrf`로 CSRF 토큰 검증
  - `authLimiter`로 레이트리밋 적용(남용/브루트포스 완화)
  - `db.collection('login').findOne({ id })`로 중복 아이디 확인
  - `bcrypt.hash(pw, 10)`으로 비밀번호 해시 생성
  - `db.collection('login').insertOne({ id, pw: hashed, em, nm })`
  - 성공 시 `res.redirect('/login')`

### 1-3. 관련 라이브러리/코드

- **라우트**: `POST /signup` (`index.js`)
- **라이브러리**
  - `bcrypt`: 비밀번호 해싱
  - `express-rate-limit`: `authLimiter`
  - `mongodb`: `login` 컬렉션 조회/저장

---

## 2) 시나리오 2: 비밀번호 찾기(Reset password)

이 플로우는 “메일로 인증코드 발송 → 코드 검증 → 새 비밀번호 저장” 단계로 진행됩니다.

### 2-1. 비밀번호 재설정 페이지 접속

- **클라이언트**: `GET /reset-password`
- **서버**: `views/reset-password.ejs` 렌더링 + `csrfToken` 주입

### 2-2. 인증코드 발송 요청

- **클라이언트**(AJAX): `POST /reset-password`
  - headers: `Content-Type: application/json`, `X-CSRF-Token: <token>`
  - body: `{ email }`
- **서버**
  - `requireCsrf` 검증
  - `emailLimiter` 레이트 리밋(메일 폭탄 방지)
  - `db.collection('login').findOne({ em: email })`로 사용자 존재 확인
  - `code = 6자리 난수` 생성 → `verificationCodes Map`에 저장
  - `transporter.sendMail(...)`로 이메일 발송
  - 성공: `{ success: true }`

### 2-3. 인증코드 검증

- **클라이언트**(AJAX): `POST /verify-code`
  - headers: `X-CSRF-Token`
  - body: `{ email, code }`
- **서버**
  - `requireCsrf` + `authLimiter`
  - `verificationCodes.get(email)`과 비교
  - 일치하면 `{ success: true }`

### 2-4. 새 비밀번호 저장

- **클라이언트**(AJAX): `POST /reset-password-new`
  - headers: `X-CSRF-Token`
  - body: `{ email, newPassword }`
- **서버**
  - `requireCsrf` + `authLimiter`
  - `bcrypt.hash(newPassword, 10)` 후
  - `db.collection('login').updateOne({ em: email }, { $set: { pw: hashed } })`
  - 사용한 인증코드 `verificationCodes.delete(email)`
  - `{ success: true }`

### 2-5. 관련 라이브러리/코드

- **라우트**: `POST /reset-password`, `POST /verify-code`, `POST /reset-password-new`
- **라이브러리**
  - `nodemailer`: SMTP 메일 발송
  - `express-rate-limit`: `emailLimiter`, `authLimiter`
  - `bcrypt`, `mongodb`

> 운영 메모: 인증코드가 메모리 Map에 저장되므로, 서버가 여러 대면 Redis 같은 공유 저장소가 필요합니다.

## 3) 시나리오 3: 로그인(Sign in)

### 3-1. 로그인 페이지 접속

- **클라이언트**: `GET /login`
- **서버**: `views/login.ejs` 렌더링 + `csrfToken` 주입

### 3-2. 로그인 폼 제출

- **클라이언트**: `POST /login` (HTML form)
  - body: `id`, `pw`, `_csrf`
- **서버**
  - `requireCsrf` + `authLimiter`
  - Passport LocalStrategy 동작:
    - `db.collection('login').findOne({ id })`
    - `bcrypt.compare(pw, user.pw)`로 검증
  - 성공 시 `req.logIn(user, ...)` 및 `req.session.user = { id, nm }`
  - 성공 리다이렉트: `/list`
  - 실패 리다이렉트: `/login?error=1`

### 3-3. 관련 라이브러리/코드

- **라우트**: `POST /login`
- **인증 구성**: `passport`, `passport-local`, `express-session`, `bcrypt`

---

## 4) 시나리오 4: 게시물 작성(Create post)

### 4-1. 목록 페이지 진입(로그인 필요)

- **클라이언트**: 로그인 성공 후 `GET /list`
- **서버**
  - 로그인 미들웨어 `로그인`으로 인증 확인
  - `ensureCsrfToken`으로 토큰 보장
  - `db.collection('post').find().toArray()`로 목록 조회
  - `views/list.ejs` 렌더링 + `csrfToken` 내려줌

### 4-2. 글 작성(모달 + fetch)

- **클라이언트**: `list.ejs`의 모달 폼에서 제목/내용 입력 후 fetch 호출
  - `POST /add`
  - headers: `Content-Type: application/json`, `X-CSRF-Token`
  - body: `{ title, content }`
- **서버**
  - `로그인` + `requireCsrf`
  - `counter` 컬렉션에서 `게시물갯수` 조회
    - 없으면 0부터 시작(초기화)
  - `_id = nextId`로 게시물 저장
  - `counter.updateOne(..., { $inc: { toTalPost: 1 } }, { upsert: true })`
  - 응답: `{ success: true, redirect: '/list' }`

### 4-3. 관련 라이브러리/코드

- **라우트**: `GET /list`, `POST /add`
- **라이브러리**: `mongodb`, (CSRF는 서버 커스텀 미들웨어), `express-session`

---

## 5) 시나리오 5: 게시물 수정(Edit post)

### 5-1. 상세 화면에서 “수정” 클릭

- **클라이언트**: `GET /edit/:id`
- **서버**
  - `로그인` + `ensureCsrfToken`
  - 게시물 조회 `db.collection('post').findOne({ _id: id })`
  - **작성자 검증**: `post.작성자_id === req.session.user.id` 아니면 403
  - `views/edit.ejs` 렌더링 + `csrfToken` 주입

### 5-2. 수정 저장(HTML form)

- **클라이언트**: `POST /edit/:id`
  - body: `title`, `content`, `_csrf`
- **서버**
  - `로그인` + `requireCsrf`
  - `db.collection('post').updateOne({ _id: id, 작성자_id: user.id }, { $set: { 제목, 내용 } })`
  - 성공 시 `/detail/:id`로 리다이렉트

### 5-3. 관련 라이브러리/코드

- **라우트**: `GET /edit/:id`, `POST /edit/:id`
- **라이브러리**: `mongodb`, `express-session`

---

## 6) 시나리오 6: 게시물 삭제(Delete post)

삭제는 **HTML form(POST)** 과 **AJAX(DELETE)** 두 경로가 있습니다.

### 6-1. 상세 화면에서 삭제(POST /delete)

- **클라이언트**: `detail.ejs`의 form 제출
  - `POST /delete`
  - body: `_id`, `_csrf`
- **서버**
  - `로그인` + `requireCsrf`
  - `db.collection('post').deleteOne({ _id: id, 작성자_id: user.id })`
  - 성공 시 `/list`로 리다이렉트

### 6-2. 목록 화면에서 삭제(AJAX DELETE /delete)

- **클라이언트**: `list.ejs`에서 jQuery `$.ajax({ method: 'DELETE', ... headers: X-CSRF-Token })`
- **서버**
  - `로그인` + `requireCsrf`
  - 작성자 조건으로 삭제
  - 성공 시 `"삭제완료"` 텍스트 응답

---

## 7) 이 시나리오에서 사용되는 핵심 라이브러리 요약

- **express**: 라우팅/미들웨어 기반 서버
- **ejs**: SSR 템플릿 렌더링(뷰)
- **mongodb**: 컬렉션 CRUD
- **passport / passport-local**: 로그인 인증
- **express-session**: 로그인 세션 유지 + CSRF 토큰 저장
- **bcrypt**: 비밀번호 해시/검증
- **nodemailer**: 비밀번호 재설정 인증코드 이메일 발송
- **express-rate-limit**: 로그인/메일발송 남용 방지
- **multer + file-type**: 이미지 업로드 처리 및 매직바이트 검증
